02 / A small, expressive robot

The desk_arm is a custom URDF model with four moving joints and a fixed tool mount.

A continuous yaw joint turns the arm about the vertical axis. Two revolute joints bend the shoulder and elbow, while a prismatic joint extends the tool. Boxes, a cylinder, and a sphere supply the visual geometry; no external mesh assets are needed.

The model has six links: base, turntable, upper_arm, forearm, slide, and tool. The upper arm and forearm are 0.65 m and 0.50 m long.

03 / Four states, one continuous loop

FINITE-STATE MACHINE · FSM

Each state specifies an absolute joint target. The FSM issues that target on entry, checks the reported joint positions, and follows its named transition when the arrival conditions are satisfied.

Transition condition. Every target joint must be within 0.02 of its target in its native unit (rad or m), and at least 1.3 s must have elapsed since state entry. This is a minimum time in the state, not an extra 1.3 s wait after arrival. The final transition returns to home.

Model & motion

Load demo sends the URDF to the parameter server and the choreography JSON to /fsm/update_logic. On each state entry, the FSM publishes a target on /joint_trajectory.

The servo approaches the target using the exact first-order update for a constant target:

qnext = q + (1 − e−4Δt)(qtarget − q)

It publishes /joint_states. This is a kinematic servo demonstration, not a torque or contact-physics simulation.

Transforms & rendering

The runtime combines each joint’s fixed URDF origin with its current motion. It publishes local transforms on /tf and accumulates them through the tree, with the root’s global pose, to produce /xform_world.

The viewer is an external TCP/JSON client. A local HTTP bridge forwards the messages to the browser. The canvas renderer reads each link’s column-major 4 × 4 world matrix, applies its URDF visual offset, projects the geometry, and draws depth-sorted faces.

The viewer receives poses from the runtime; it does not recompute FK. The public page plays the recorded output and needs no running Python server.
